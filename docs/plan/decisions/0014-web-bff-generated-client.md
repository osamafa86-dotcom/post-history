# 0014 — نواة الويب وعميل العقد والجلسة خلف BFF

- الحالة: مقترح للمراجعة ضمن التذكرة #81
- التاريخ: 2026-10-20
- المسؤول: الويب
- بند ملحق القرارات: 6 للمشغّل النهائي فقط؛ القرار الحالي مؤقت ولا يحسمه

## السياق

تحتاج غرفة الأخبار واردًا للقراءة بالعربية والإنجليزية، يحفظ استقلال الحالات الثلاث ويستهلك العقد المجمّد. رموز التحديث تدور مرة واحدة؛ تجديد طلبين متزامنين بالرمز نفسه قد يُبطل جلسة المستخدم. ولا يجوز وصول أسماء المصادر أو الموقع الدقيق إلى روابط الواجهة أو سجلاتها. تحدد #81 الاستطلاع عبر `/notifications` والمشغّل البسيط لهذه الدورة؛ لا يُبنى WebSocket أو محرر.

## الخيارات

1. رموز API في تخزين المتصفح: مرفوض لوصول JavaScript إليها ولخطر إعادة استخدامها بعد تبديل الحساب.
2. رمزا الوصول والتحديث في كوكيز منفصلة دون حالة على BFF: يُخفيهما عن JavaScript، لكن استجابات التدوير المتزامنة بين التبويبات أو نسخ الخادم قد تستبدل الكوكي بزوج قديم؛ قفل داخل عملية واحدة لا يكفي.
3. كوكي جلسة ويب معتم `HttpOnly` ورموز API مشفّرة في Redis مع قفل موزّع لكل جلسة: المختار. الكوكي رمز وصول للـ BFF وحده، وليس JWT الخادم؛ لا يعاد أي زوج رموز في JSON أو HTML.

## القرار

- Next.js 16.4.2 (App Router)، React 19.3.1، TypeScript 5.9.3 وTailwind 4.3.3 بإصدارات صريحة وlockfile مستقل. الصفحات الخاصة ديناميكية ولا تُخزّن استجاباتها مؤقتًا. التتبّع المدمج معطّل، والخطوط من الجهاز فقط.
- `openapi-typescript` 7.13.0 يولّد أنواع العقد بما فيها المخططات الخارجية، و`openapi-fetch` 0.17.0 عميل التشغيل. السكربت يولّد الأنواع ومصنع العميل في مجلد مؤقت ويقارن الناتج حرفيًا في CI، دون تعديل العقد أو كتابة نماذج API يدوية. نوع النموذج مشتق من الناتج مع إسقاط `$defs`، لأنها كلمة في JSON Schema وليست حقل بيانات.
- مصدر التوليد المؤقت، بتوجيه المنسّق في #81: فرع `agent/contracts/v0.1-post-freeze` في #58 عند `fc9e627514ade2e9857f3da8358de074f462e768`. يقرأ CI العقد من checkout مستقل مثبت بهذا الرأس. بعد الدمج يُزال الاستثناء ويُعاد التوليد من `main`؛ لا يُغيَّر `contracts/` هنا.
- i18n بقواميس `messages/ar.json` و`messages/en.json` ومسار لغة صريح؛ العربية الافتراضية، و`Intl` للتواريخ. لا حاجة لحزمة ترجمة إضافية في نطاق الشاشات الحالية؛ اختبار يفرض تساوي المفاتيح.
- يعزل Route Handler المسارات المتاحة: قراءة الهوية والمواد والنماذج والإشعارات، ودخول وخروج فقط. يستعمل العميل المولّد خلفه. كل كتابة تحمل `Idempotency-Key`، بما فيها الهوية رغم استثنائها من تخزين مفاتيح المنع في عقد v0.
- الكوكي `__Host-ph-session`: عشوائي 256 بت، `HttpOnly` و`Secure` و`SameSite=Strict` و`Path=/`، بلا Domain. يُسمح بالـ HTTP فقط بإعداد محلي صريح وعلى عنوان loopback لكل من الويب وAPI. الجلسة عمرها المطلق ثماني ساعات، بلا تمديد عند القراءة. رموز API مشفّرة بـ AES-256-GCM في Redis بمفتاح من البيئة. تغيير المفتاح يُنهي جلسات الويب القديمة.
- التدوير مبكر قبل انتهاء الوصول بـ15 ثانية، تحت قفل Redis لكل معرّف جلسة؛ يقرأ المنتظرون الزوج الجديد من المخزن. مدة القفل 45 ثانية مقابل مهلة 8 ثوانٍ لكل اتصال، وبحد أقصى خمسة اتصالات متسلسلة لمسار الوسائط شاملاً التدوير ووصول ترويسات التخزين؛ يُبث الجسم خارج القفل. لا تُعاد عملية تدوير ذات استجابة مجهولة، لأن الرمز قد استُهلك بالفعل؛ تُمحى الجلسة ويُطلب الدخول.
- كل 401 أثناء القراءة يمحو حالة BFF والكوكي ويعيد الواجهة إلى الدخول برسالة الإبطال. الخروج من الجميع له تأكيد مستقل يذكر إلغاء الرفوع؛ لا تدّعي الواجهة نجاحه عند فشل اتصال API. لا حفظ محلي للمواد أو القيم أو الرموز؛ تبديل الحساب/إظهار التبويب يعيد فحص الهوية ويمحو الشاشة السابقة.
- حماية الطلبات الكاتبة بفحص Origin المطابق لإعداد الخادم وترويسة خاصة وJSON، مع حجب الجلسة عن JavaScript. استجابات خاصة `no-store`، وسياسة CSP بـ nonce لكل استجابة، ومنع التضمين وReferer. لا تمرّر الواجهة رسائل أخطاء الخادم الخام.
- الوارد يستطلع كل 15 ثانية تسلسليًا ويعيد الجلب عند عودة الاتصال؛ إخفاء التبويب يزيل محتواه ويوقف استطلاعه. المرشحات من قائمة أعمدة العقد فقط. فرز محلي للصفحة معلن صراحة؛ لا نخترع معامل sort للخادم.
- راسم النماذج يستخدم قواعد العقد والحَكَم المشترك. قيود v0 تمنع حقول الموقع والحقول الحساسة؛ توجد بوابتان مستقلتان للقراءة تحسبًا لرفع القيد بعقد لاحق، ولا يُعرض حقل مجهول أو محجوب. صفحة المادة تستخدم مخطط الإصدار الذي حفظته المادة، لا أحدث نموذج.
- HTML5 MP4 هو المشغّل المؤقت؛ لا يحسم Video.js مقابل Shaka. يعرض مشتق proxy والمصغّرات المتحققة بعلامة داخلية، عبر مسار BFF من النطاق نفسه. يطلب `getDerivativeUrl` رابط العقد الموقّع بعد التحقق من عضوية الملف وحالته وصلاحية قراءة المادة؛ الرابط يبقى في الخادم. قائمة `WEB_MEDIA_ORIGINS` تحصر التخزين بأصول المشروع، وتُرفض التحويلات وMIME غير المتوقع، ولا تنتقل رموز API أو كوكيز إلى التخزين. الأصل والملاحظة الصوتية وHLS لا تعرضها هذه التذكرة. إخفاء زر التنزيل ليس DRM ولا حمايته مفترضة.
- لا تخزين لروابط المشتقات: تُجلب من جديد لكل طلب بما فيه Range، وتُرفض الروابط المنتهية أو التي تتجاوز عشر دقائق. عناصر الوسائط تعيد فحص الهوية والمحاولة مرة واحدة عند الخطأ ثم تعرض عدم الإتاحة. الترويسات الخاصة تمنع التخزين المؤقت؛ تدفق الجسم محدود بمهلة 120 ثانية وبإلغاء الطلب. لا تحليلات أو طباعة للرابط الموقّع.

## التبعات والقرارات المطلوبة

1. يحتاج نشر الويب Redis ومفتاح جلسة وHTTPS وإعداد Origin صحيحًا؛ تنسيق تهيئتها مع مالك البنية، دون تعديل `infra/` في هذا الطلب. تعطل مخزن الجلسات يمنع الوصول ولا ينزل إلى جلسات غير آمنة في الذاكرة. مراجعة حدود المعدل على API مطلوبة لأن اتصالات BFF تأتي من الخادم نفسه.
2. نقطة المشتقات موجودة في #58 بعد سؤال #81، ومرتبطة هنا بالعميل المولّد. دمجها المقرر حسب المنسّق في 2026-11-02 وتنفيذها في API متطلب للتشغيل الحقيقي. اختبارات الفيديو والمصغّرات وانتهاء الرابط تستخدم API وتخزينًا اصطناعيين مع BFF وRedis فعليين؛ لا إثبات تكامل مع العامل/API المنشور حتى الآن. اختيار أصول التخزين وضبط مهل تدفق الوسائط يتطلبان تنسيق النشر مع البنية.
3. لا يحدد العقد اسم المصور عند `display_name.mode=real_name`؛ يعرض الويب الاسم المستعار/اسم الشبكة أو بديلًا عامًا. ولا يوجد sort عام؛ الفرز يخص الصفحة الحالية.
4. `gps` writeOnly وحقول `sensitive/location` محظورة في v0. لا طلب قراءة لهذه القيم ولا عرض افتراضي؛ ظهورها المخوّل يتطلب أولًا عقدًا واضحًا وآلية تدقيق من مالكه.
5. النسخة لا تكتب إجراءات مراجعة أو إدارة نماذج. #82 و#83 مؤجلتان حتى دمج السابقة. مالك الجودة يراجع وظيفة `web` في CI، والمنسّق وحده يدمج بعد مراجعتي الجودة والأمن.

## إضافة: الرفع من الحاسوب بـ tus (#88، 2026-10-21)

- **المسار:** المتصفح يرفع مباشرة إلى `tus_endpoint` الذي يعيده `POST /uploads`، لا عبر الـBFF؛ الـBFF يمرّر كتابات الإنشاء الثلاث (`POST /materials` و`POST /uploads` و`POST /uploads/{id}/web-ingest-token`) وقراءة `GET /uploads/{id}` بقوائم بيضاء للحقول، وبدور المراسل وحده كما في `x-roles` للعقد. لا تغيير في العقد.
- **الرموز في المتصفح:** رمز الرفع ورمز ingest يصلان إلى المتصفح لأنه من يرفع، ويبقيان في ذاكرة الصفحة وحدها. الـBFF يرفض (502) أي `tus_endpoint` خارج `WEB_TUS_ORIGINS`، والمتصفح لا يتبع `Location` خارج نقطة الإنشاء، وCSP `connect-src` يحصر الاتصال في الأصول نفسها. رمز ingest يُطلب عند الحاجة ويُجدَّد قبل انتهائه بدقيقة وعند 401 من البوابة، و401 من الـBFF عند التجديد (جلسة الدخول أُبطلت) يوقف الرفع ويخرج المستخدم. 403 من البوابة لا يميّز سببه، فيسأل المتصفح الـBFF عن الجلسة ليفرّق الإبطال عن انتهاء جلسة الرفع.
- **المكتبة:** `@uppy/core` 6.2.0 و`@uppy/tus` 6.0.0 (فوق `tus-js-client` 4.3.1) مثبّتة. حجم الجزء = `part_size_bytes` من الخادم. حفظ tus-js-client في localStorage معطّل (`urlStorage` فارغ).
- **البصمة:** `client_sha256` إلزامي عند الإنشاء، فيُحسب الملف كله قبل الرفع. Web Crypto لا يعرض بصمة تزايدية، فالحساب بـ `@noble/hashes` 2.4.0 (SHA-256 بلا اعتماديات) في Worker على شرائح 8 MiB، فلا يُحمَّل الملف في الذاكرة. `client_fingerprint` (أول وآخر 1 MiB) بـ Web Crypto. `/uploads/{id}/complete` لا يُستدعى: في مسار tusd يرد الخادم 409 (الاكتمال يصل من خطّاف post-finish)، والمقارنة بالبصمة يجريها الخادم بـ `client_sha256`.
- **الاستئناف بعد إغلاق التبويب:** IndexedDB (`post-history-uploads`) يحفظ لكل ملف (الاسم والحجم ووقت التعديل): المادة، ومفتاح عدم التكرار وجسم `POST /uploads`، ومعرّف الجلسة وعنوان tus. لا رمز فيه. إعادة اختيار الملف نفسه تستأنف: بعنوان tus عبر HEAD، أو قبل إنشاء رفع tus بإعادة `POST /uploads` بالمفتاح نفسه (يعيد الخادم الجلسة برمز جديد ما دامت `created`). عنوان tus قدرة حاملة (SEC-06)، لكنه لا يقبل بايتًا عبر البوابة دون رمز ingest لجلسة دخول حية للمستخدم نفسه. يُمسح السجل عند الخروج والإبطال، وتنتهي السجلات بانتهاء الجلسة.
- **حدود:** المرفقات في النموذج الديناميكي لا تُرفع بعد، فلا تُرسل قيمتها. الويب يرفع الأصل وحده (لا نسخة خفيفة في المتصفح). الطاقم وفريق الإنتاج لا يرفعون حتى يوسّع العقد `x-roles` لـ `/materials` و`/uploads`.
- **تبعية بنية:** المتصفح على أصل غير أصل tus يحتاج CORS من tusd خلف البوابة: `-cors-allow-origin` بأصل الويب و`-cors-allow-headers Ingest-Token`، والبوابة تمرّر OPTIONS أصلًا. لا يُعدَّل `infra/` هنا.
