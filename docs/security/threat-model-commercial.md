# نموذج التهديد — المرحلة التجارية (المتجر والتراخيص والمدفوعات والمستحقات)

- المسؤول: وكيل 10 — الأمن والمراجعة
- الإصدار: 0.1 (2026-10-21)، بقرار المالك بناء المرحلة التجارية الآن بمزوّد دفع تجريبي (#148)
- النطاق: الكتالوج والمعاينة، والتراخيص، وطبقة الدفع وإشعارات البوابة، والدفتر والمستحقات والصرف، والتسليم، ولوحات المالية. يكمّل `threat-model.md` ولا يكرره.
- المرجع: الخطة، قسم «المتجر والتراخيص والمدفوعات والعمولات»، و`CLAUDE.md` §5.
- الإفصاح: كما في `threat-model.md` §9. الملفات العامة تذكر الضوابط والمُصلح، والثغرة المفتوحة تُبلَّغ بقناة خاصة.

المبدأ الحاكم يبقى كما هو: **ما يكشف مراسلًا لا يُصحَّح بإصدار لاحق.** المتجر واجهة عامة للإنترنت، فكل حقل يظهر فيه يُعامل كأنه منشور.

## 1. الأصول الجديدة

| # | الأصل | الحساسية | ما نحميه فيه |
| --- | --- | --- | --- |
| B1 | الأصل والنسخ المرخّصة (ملفات التسليم) | عالية | لا تُنزَّل إلا بترخيص نافذ؛ لا تسرّب بيانات كاشفة |
| B2 | المعاينة بعلامة مائية | متوسطة | لا تكشف الأصل ولا تُغني عنه، ولا تحمل وسومًا كاشفة |
| B3 | سجل البيعة المجمّد (الشروط، السعر، الإصدار، رقم الترخيص) | عالية | لا يُعدَّل بعد التأكيد |
| B4 | دفتر الأستاذ والأرصدة | حرجة | قيود لا تُعدَّل ولا تُحذف؛ الرصيد محسوب منها |
| B5 | بيانات الصرف (حسابات المراسلين البنكية والمحافظ، وثائق التحقق من الهوية) | حرجة | سرية، وتكشف هوية المراسل الحقيقية |

| B8 | قواعد العمولات والأسعار والكوبونات | عالية | لا تُغيَّر إلا بصلاحية ومدقَّقة |

## 2. الخصوم الإضافيون

- **C-T1 مشترٍ محتال:** بطاقة مسروقة، أو اعتراض على دفع بعد التنزيل، أو تكرار الاسترداد، أو مشاركة رابط التنزيل.
- **C-T2 مهاجم على إشعارات البوابة:** يزوّر إشعار «تم الدفع» أو يعيد إرسال إشعار حقيقي.
- **C-T3 داخلي مالي:** موظف مالية أو مدير يعدّل نسبة أو رصيدًا أو حساب صرف لمصلحته، أو يصرف دون اعتماد ثانٍ.
- **C-T4 كاشط الكتالوج:** يجمع المعاينات أو يعيد بناء الأصل منها، أو يستخرج منها ما يكشف المراسل.
- **C-T5 مؤسسة مشترية أخرى:** تحاول قراءة طلبات مؤسسة منافسة أو فواتيرها أو تراخيصها الحصرية.
- **C-T6 جهة معادية للمراسل:** تستخدم الكتالوج أو صفحة التحقق العامة أو بيانات الصرف لتحديد هوية المراسل وموقعه.

## 3. السيناريوهات والضوابط

### C1 — بيانات البطاقات والدفع المستضاف

| الضابط | المرجع |
| --- | --- |
| صفحة دفع مستضافة لدى البوابة وحدها؛ لا حقل بطاقة في واجهتنا ولا مرور لرقمها بخوادمنا ولا سجلاتنا | الخطة: طبقة الدفع؛ PCI DSS SAQ A |
| ما نحفظه من البوابة: معرّف العملية والمبلغ والعملة والحالة وآخر أربعة أرقام إن لزمت، لا أكثر | يطلبه هذا النموذج |
| إعادة التوجيه بعد الدفع إلى مسار ثابت عندنا، لا إلى عنوان من وسيط الطلب | يطلبه هذا النموذج |
| مزوّد الدفع التجريبي ومفاتيحه في بيئة الاختبار وحدها؛ preflight يرسب إن وُجد مفتاح تجريبي في الإنتاج أو العكس | يطلبه هذا النموذج |

### C2 — إشعارات البوابة (Webhook): التوقيع والتكرار والترتيب

| الضابط | المرجع |
| --- | --- |
| الملفات لا تُفتح بصفحة «تم الدفع» في المتصفح؛ التأكيد من إشعار البوابة الموقّع إلى الخادم وحده | الخطة: أنواع التراخيص |
| التحقق من التوقيع على الجسم الخام قبل أي تحليل، بمقارنة ثابتة الزمن، مع نافذة زمنية للطابع الزمني إن وفّرته البوابة | يطلبه هذا النموذج |
| معرّف حدث البوابة فريد في قاعدة البيانات؛ الإعادة لا تُنشئ ترخيصًا ولا قيدًا ثانيًا (اختبار `duplicate-payment`: عشر مرات وبترتيب مختلف) | الخطة: اختبارات القبول |
| حالة الدفع آلة حالات أحادية الاتجاه؛ إشعار متأخر لا يعيد حالة متقدمة إلى الوراء | يطلبه هذا النموذج |
| المبلغ والعملة والطلب في الإشعار تُقارن بما أنشأناه في جلسة الدفع، والفرق رفض مدقَّق | يطلبه هذا النموذج |
| نقطة الإشعار لا تقبل إلا مسار البوابة وطرقها؛ حد معدل، ولا تكشف في ردها سبب الرفض | يطلبه هذا النموذج |
| تسوية يومية آلية مع كشف البوابة تكشف ما فات الإشعارات أو زاد عليها | الخطة: طبقة الدفع |

### C3 — سلامة الدفتر

| الضابط | المرجع |
| --- | --- |
| قيد مزدوج لا يُعدَّل ولا يُحذف، يُفرض بصلاحيات قاعدة البيانات (سحب UPDATE وDELETE من حساب التطبيق) ومحفّز، لا بالاتفاق | الخطة: دفتر الأستاذ |

| التصحيح بقيد عكسي مدقَّق، لا بتعديل | الخطة |

| النسبة والسعر وسعر الصرف المطبَّقة تُجمَّد في سجل البيعة لحظة التأكيد | الخطة |

### C4 — روابط التنزيل المرخّصة والتسليم

| الضابط | المرجع |
| --- | --- |
| الرابط موقّع، عمره ≤ 24 ساعة، وعدد مرات محدود، ومربوط بالترخيص والإصدار ونوع التسليم المشترى (أصل أو نسخة منتجة) | الخطة: التسليم |
| يُصدَر فقط والترخيص نافذ؛ الاسترداد أو الاعتراض يوقف الإصدار الجديد فورًا | يطلبه هذا النموذج |
| ملف التسليم بلا بيانات كاشفة (GPS، معرّف الجهاز، أسماء محمية)، كحزمة التصدير (#126، R9) | `CLAUDE.md` §5 |
| عزل المؤسسات: مؤسسة لا ترى طلبات أو فواتير أو تراخيص غيرها، ويرد ما خارجها `404` (اختبار `tenant-isolation`) | S6 في `threat-model.md` |
| الحصرية: قفل صف وحجز مؤقت وفهرس فريد جزئي في قاعدة البيانات، لا في الكود وحده (اختبار `rights-exclusivity`) | الخطة: أنواع التراخيص |
| صفحة التحقق العامة تثبت صلاحية رقم الترخيص ونوعه ومدته فقط؛ بلا اسم المشتري ولا السعر ولا اسم المراسل الحقيقي | يطلبه هذا النموذج |
| رقم الترخيص غير قابل للتخمين أو التعداد، وحد معدل على صفحة التحقق | يطلبه هذا النموذج |

## 4. قائمة مراجعة طلبات العقد v0.3 والتنفيذ

تُطبَّق مع `pr-checklist.md`. كل بند يجيب «نعم» أو يذكر سببًا.

1. **العقد:** كل مسار تجاري يحمل `x-roles`، ولا مسار عام يعيد حقلًا من B5 أو اسمًا حقيقيًا أو إحداثيات.
2. **العقد:** مخطط إشعار البوابة داخلي غير معلن، والتوقيع والمعرّف الفريد للحدث موصوفان.
3. **العقد:** كل كتابة مالية تحمل `Idempotency-Key`، وحمولة أحداث Outbox المالية قائمة بيضاء بالمعرّفات والمبالغ.
4. **التنفيذ:** لا رقم بطاقة ولا سر بوابة في كود أو سجل أو اختبار؛ أسرار البوابة من البيئة وتُدوَّر.
5. **التنفيذ:** التحقق من توقيع الإشعار قبل التحليل، والإعادة لا تكرر شيئًا (`duplicate-payment`).
6. **التنفيذ:** جدول القيود محمي بصلاحيات قاعدة البيانات ومحفّز، مع اختبار سلبي.
7. **التنفيذ:** رابط التنزيل مربوط بالترخيص النافذ، ويتوقف بالاسترداد، والملف بلا وسوم كاشفة.
8. **التنفيذ:** الحصرية في قاعدة البيانات لا في الكود (`rights-exclusivity`).
9. **التنفيذ:** فصل الصلاحيات واعتماد الشخصين مختبران بأدوار متعددة.
10. **التنفيذ:** المعاينة مشتق بعلامة مدمجة، لا تكشف الأصل، والمادة الحساسة خارج الكتالوج.
11. **التنفيذ:** صفحة التحقق العامة لا تكشف المشتري ولا المراسل.

## 5. ما يحتاج قرارًا بشريًا

- حد المبلغ الذي يستلزم اعتماد شخصين، ومهلة تعليق الصرف بعد تغيير حساب الصرف.
- ما تعرضه صفحة التحقق العامة بالضبط (مقترح: الصلاحية والنوع والمدة فقط).
- مدة الاحتفاظ بوثائق التحقق من الهوية.
