# الويب — النواة وإجراءات المراجعة (#81، #82)

Next.js بالعربية RTL والإنجليزية: الدخول، الوارد المرقّم، تفاصيل المادة وإجراءات مراجعتها، الإدارة والإشعارات، ومعاينة النموذج والتحقق المحلي. القرار والحدود في `docs/plan/decisions/0014-web-bff-generated-client.md`.

## التشغيل

Node.js 22، API الحالي، وRedis. من `apps/web`:

```bash
npm ci
cp .env.example .env.local
# املأ WEB_SESSION_KEY بقيمة عشوائية: openssl rand -base64 32
# واضبط API_BASE_URL وWEB_REDIS_URL وWEB_ORIGIN وWEB_MEDIA_ORIGINS.
npm run dev
```

يفتح `http://127.0.0.1:3100` العربية افتراضيًا. `npm run build && npm start` لبناء الإنتاج. إعداد HTTP المحلي لا يعمل إلا مع loopback؛ النشر يحتاج HTTPS، وإلغاء `WEB_ALLOW_INSECURE_LOCALHOST`، ومفتاح من خزنة الأسرار. لا متغير `NEXT_PUBLIC` يحمل بيانات اعتماد. لا تضع `.env.local` في Git.

الرمز الوحيد في المتصفح معرّف جلسة ويب داخل كوكي `HttpOnly`، ورموز API مشفّرة في Redis. قراءة البيانات عبر BFF تضيف مصادقة الخادم ولا تقبل عنوان API من المستخدم. لا localStorage ولا حفظ نماذج محلي ولا اتصال بخطوط أو تحليلات خارجية.

## الفحوص

العميل مولّد من العقد الحالي في `main` (v0.2، بعد دمج #58 وتحديثاته). أُزيل checkout المؤقت من وظيفة `web` بتوجيه المنسّق في #82؛ يفحص CI العقد داخل نسخة المستودع نفسها. شغّل الأوامر من `apps/web`:

```bash
npm run lint
npm run typecheck
npm run check:client
WEB_TEST_REDIS_URL=redis://127.0.0.1:6379/1 npm test
npm ci --prefix ../../tools/acceptance
npm run test:conformance
npm run build
npx playwright install chromium --only-shell
WEB_TEST_REDIS_URL=redis://127.0.0.1:6379/1 npm run test:e2e
node scripts/validate-measurements.mjs
```

اختبار Redis وحده يُتخطى إذا غاب عنوان الاختبار محليًا؛ CI يمرره ويشغّله إلزاميًا. اختبارات المتصفح تحتاج Redis أيضًا؛ Playwright يبدأ API اصطناعيًا على 3201 وNext.js على 3100، ويستعمل بيانات مخترعة فقط. النصوص المشتركة للنماذج تُقرأ من موضعها، ولا يشغّل الويب التنفيذ المرجعي بدل مدققه.

`tests/media-fixture.json` عينة هندسية مولّدة محليًا بـ FFmpeg: مستطيلان ملونان لمدة ثانيتين وPNG، دون أي محتوى مراسلين. ملف MP4 الاختباري بترميز VP9 لأن Chromium المفتوح المصدر في Playwright لا يدعم H.264؛ الاختبار يثبت تشغيل HTML5 ومسار BFF وتجديد الرابط، ولا يثبت توافق خرج العامل H.264 مع كل المتصفحات. يلزم اختبار ذلك في Chrome/Safari/Firefox المستهدفين مع API والعامل الفعليين قبل النشر.

`npm run generate:client` يعيد توليد المصدر الملتزم عند تغيير العقد من مالكه. `check:client` يولّد إلى مجلد مؤقت ويفشل عند أي فرق، ولا يصلح الفرق تلقائيًا.

## إعادة القياس

شغّل Redis، ثم `node --import tsx scripts/fixture-api.ts`، واضبط `API_BASE_URL=http://127.0.0.1:3201/v1` وإعدادات BFF المحلية، وابنِ وشغّل `npm start`. من نافذة أخرى: `npm run measure`. يستخدم السكربت حساب الاختبار الاصطناعي فقط؛ لا يُشغَّل ضد API الإنتاج. اجتياز أربع صفحات يثبت وجود 200 مادة؛ زمن العرض الأول يخص أول 50 صفًا، كما يصرّح ملف القياس. يمكن تغيير مسار الملف الناتج بـ `WEB_MEASUREMENT_OUTPUT`.

## حدود العقد الحالي

- `getDerivativeUrl` يستهلك `/materials/{id}/files/{file_id}/download-url` المضاف في #58. يعرض MP4 والمصغّرات `verified` عبر BFF من النطاق نفسه؛ لا يُرسل رابط التخزين إلى المتصفح. كل طلب Range يعيد فحص الجلسة والمادة ويأخذ رابطًا جديدًا بعمر ≤10 دقائق. إعادة محاولة واحدة عند فشل الوسائط، ثم رسالة غير متاح وزر إعادة المحاولة.
- `WEB_MEDIA_ORIGINS` قائمة أصول تخزين المشتقات التابعة للمشروع فقط؛ الفراغ يمنع المعاينات. لا redirects ولا Authorization أو Cookie نحو التخزين؛ MIME مقيد بـ MP4 وJPEG/PNG/WebP. الأصل والملاحظة الصوتية وHLS ليست مسارات عرض متاحة في هذه التذكرة. الترويسات مهلة 8 ثوانٍ، والجسم يُبث دون تجميع بمهلة 120 ثانية لكل طلب؛ يلزم ضبط المهلة والبنية للروابط البطيئة قبل النشر.
- تشغيل الخادم الحقيقي يعتمد على دمج وتنفيذ نقطة العقد الجديدة؛ عند غيابها تظهر المعاينة غير متاحة. الاختبارات تثبت المسار على بيانات اصطناعية ولا تدّعي جاهزية API المنشور.
- اسم `real_name` غير متاح؛ يستخدم الاسم المستعار أو اسم الشبكة أو بديلًا عامًا.
- الفرز محلي للصفحة فقط؛ المرشحات المرسلة للخادم أعمدة صريحة من العقد.
- GPS writeOnly؛ لا حقول location/sensitive منشورة في v0. الحجب على BFF والراسم احترازي ويُختبر بالصلاحيتين منفصلتين.
- API اصطناعي في اختبارات المتصفح والقياس؛ ليس اختبار نشر كامل على PostgreSQL أو أجهزة الفريق الفعلية.
- اختبار المرفق يطابق القيمة المجردة `{mime, size_bytes}` للحَكَم المشترك؛ لا يرسلها إلى API ولا ينفذ رفع المرفقات. قيمة الحفظ النهائية يحددها `attachment-value.json` عند بناء مسار الكتابة لاحقًا.

## إجراءات المراجعة (#82)

توسيع للمسارات الصريحة وعميل العقد وحماية الجلسة في ADR 0014؛ لا حزمة جديدة ولا مزوّد خارجي. التحويلات تعرض الحالات الفنية والتحريرية والحقوقية مستقلة، وتخفي التحويلات التي يكتبها الخادم والحالة التجارية المؤجلة `sellable`. خيارات الواجهة تعتمد على الدور والملكية الظاهرة؛ API هو صاحب القرار النهائي للنطاق وحيوية الحجز وقواعد الانتقال.

- يرسل التحويل وتعديل المساهمين والحجز `If-Match` من ETag المادة أو `row_version` الآمن، وليس `version` الخاص بإصدار المحتوى. غياب المراجعة يعطّل الكتابة. يتوقف تحديث المادة أثناء التحرير، وتبقى المسودة عند 412 إلى أن يطلب المستخدم إعادة التحميل صراحة.
- يمنع زر الإجراء الطلب المتزامن، ويبقى `Idempotency-Key` نفسه في ذاكرة الشاشة عند انقطاع الاتصال أو 5xx وإعادة الطلب نفسه. لا إعادة إرسال تلقائية ولا حفظ محلي للمسودات. إعادة تحميل الصفحة تتخلص من المسودة ومفتاحها؛ عند نتيجة غير مؤكدة يُستخدم زر الإجراء نفسه قبل مغادرة الصفحة.
- كل POST/PUT/DELETE إلى BFF يحتاج Origin مطابقًا وJSON وترويسة الواجهة؛ تُقرأ `/auth/me` من جديد قبل كل كتابة. توجد قائمة مسارات وأدوار وحقول صريحة، وحد 8 KiB للجسم، ولا يُعاد خطأ API الخام. لا proxy عام ولا تعديل للمواد أو النماذج خارج هذه التذكرة.
- قائمة المساهمين تُستبدل كاملة؛ مجموع النسب 100% بمنزلتين عشريتين ومعرّفات غير مكررة. يشمل الحجز الإنشاء والفك؛ الخادم يفرض انتهاء الحجز والنطاق.
- صفحة `/ar/admin` لدور `system_admin` فقط. كل صلاحية قراءة لها إجراء منفصل وتأكيد يبيّن الحساب والصلاحية. تعليق الحساب وإعادته يرسلان `{status: suspended|active}` فقط حسب العقد؛ reason_code يُشتق في API للتدقيق، ولا يُرسل نص حر لهذا الإجراء. تمنع الواجهة وBFF تعليق الحساب نفسه.
- ملحق #82 بعد #130 و#135: الصلاحيات الثلاث مستقلة، ومنها `reporter_identity:read`. سجل المنح والسحب عبر `/users/{id}/permissions/history` مقسّم بالمؤشر، والأحدث أولًا؛ يتضمن تغييرات سياسة الهوية العامة. يعرض المعرّفات والأكواد فقط، ويسقط الأسباب الحرة والحقول غير المعروفة. تغيير المستخدم يلغي الطلب السابق ويزيل سجله، وفشل القراءة لا يعرض سجلات قديمة. لا يُستنتج وضع المنح الحالي من صفحة تاريخية جزئية؛ لا نقطة قائمة مستخدمين في العقد.
- الإشعارات تستطلع كل 15 ثانية وتدعم مؤشر الصفحات والقراءة والإقرار ومرشح غير المقروءة. عنوانها عام من الموارد؛ BFF يسقط `title` و`type` الخامين، ولا ينقل إلا رابط مادة بمعرّف UUID. سجل حالات المادة يعرض المسار والحالتين والفاعل والوقت ويُسقط السبب الحر.

اختبارات `review.test.ts` و`review-bff.test.ts` تغطي الأدوار والصلاحيات المستقلة وIf-Match و412 وCSRF ومفاتيح إعادة المحاولة والحجب. `e2e/review.spec.ts` يشغّل الشاشات الجديدة على بناء الإنتاج مع Redis فعلي وAPI اصطناعي ذي مراجعات وسجل منع تكرار مستقل؛ ليس بديلًا لاختبار API/PostgreSQL الفعليين. لا قياس أداء جديد في #82 ولا ادّعاء زمن أو جاهزية إنتاج.

دُمج إصلاح #125 لتمرير عنوان العميل إلى الدخول والتجديد فقط عند تمكين WEB_TRUST_FORWARDED_FOR. لا يُفعّل إلا خلف حافة تستبدل X-Forwarded-For وتمنع الوصول المباشر إلى BFF، مع BFF_SOURCE_ADDRESSES الدقيق لدى API. يُحافظ هذا الطلب على الإصلاح واختباره؛ ضبط النشر من مسؤولية البنية.

## إعداد هوية المراسل وسجل الصلاحيات (ملحق #82)

بطاقة `GET/PUT /admin/settings/reporter-identity` لمدير النظام، وفق ADR 0021. الافتراضي `separate` يتطلب `reporter_identity:read`؛ اختيار `protected_source` يجعل صلاحية المصادر المحمية هي المطلوبة. تعرض الواجهة أثر السياسة قبل الحفظ، وتطلب واحدًا من أسباب العقد الأربعة وتأكيدًا صريحًا. يُمسك مفتاح إعادة المحاولة في ذاكرة البطاقة، ويُحدَّث الإعداد من رد الخادم بعد النجاح فقط؛ لا تحفظ مسودات أو أسماء مراسلين. يُسقط BFF الاسم الحقيقي حتى مع وجود صلاحية القراءة، فهذه الدفعة لإدارة الوصول وسجله وليست لعرض الأسماء.

`tests/contract-drift.test.ts` يقرأ `contracts/openapi.yaml` الفعلي ويطابق قوائم الصلاحيات وأسباب الإعداد وخياراته وحدود طول السبب والصفحات ومسارات الكتابة وطرقها والحالات الثلاث. أصبحت `js-yaml` الموجودة أصلًا ضمن سلسلة أدوات التطوير اعتمادًا مباشرًا مثبتًا للاختبار فقط؛ لا اعتماد تشغيل جديد.

اختبار القبول الشامل للويب **جزئي**: اختبارات المتصفح تبني Next.js وتشغّل Redis حقيقيًا مع API اصطناعي، ولا تشغّل مسار BFF ضد API وPostgreSQL الفعليين. سكربتات `tools/acceptance` الخاصة بالخادم لا تُحتسب إثباتًا لذلك المسار؛ يلزم تشغيل قبول BFF حي من مالك الجودة قبل اعتماد جاهزية النشر. لا قياس أداء جديد أو ادّعاء جاهزية إنتاج في هذا الملحق.

## قواعد التنبيه (#203 بند 7)

صفحة `/ar/notification-rules`. مدير النظام يقرأ ويكتب، ورئيس التحرير يقرأ وحده، كما في `x-roles`. القائمة والقراءة المفردة بقائمة بيضاء ومعها ETag. الإنشاء والاستبدال والحذف بمفتاح عدم التكرار. الاستبدال والحذف بـ `If-Match` من القراءة المفردة، و412 يحفظ النموذج ويطلب إعادة الفتح. `ruleInput` يطبّق قواعد العقد قبل الإرسال:
- مستلم واحد على الأقل، وقناة واحدة على الأقل؛
- مستويات تصعيد متتالية بمهل متزايدة، ولا تصعيد بلا مهمة؛
- نطاق متسق، وساعات هدوء صالحة.

قوائم الأحداث والقنوات والأدوار والحدود يطابقها `contract-drift` مع العقد. الاختبارات في `tests/notification-rules.test.ts` و`e2e/notification-rules.spec.ts`.
## مكوّنات المتجر (#203 بند 27)

مكوّنات عرض في `src/components/store/`، لا صفحة بعد: بطاقة الكتالوج، والمعاينة بطبقة هوية المشاهد بلا تنزيل، واختيار الترخيص، والسلة. الأشكال في `src/lib/store-format.ts` بنيوية مطابقة لـ `Money` و`LocalizedText` و`CatalogItem` في عقد v0.3 (#178). تُستبدل بالأنواع المولَّدة عند دمجه، ولا تُستدعى نقطة قبل ذلك. المجاميع لكل عملة على حدة، ولا تُجمع USD وILS (ADR 0025). الحصري يُعطَّل حين `exclusive_available=false`، والتجاري يُعلَّم بموافقة الإدارة. الاختبار في `tests/store-components.test.tsx`.

## لوحة غرفة الأخبار (#203 بند 4)

صفحة `/ar/board` للمشرف والمنتج ورئيس التحرير ومسؤول الحقوق ومدير النظام، كما في `x-roles`. اللقطة `/dashboard/newsroom` كل 5 ثوانٍ، بقائمة بيضاء في `safeDashboard` تحفظ الحالات من قوائم العقد والمعرّفات والأرقام وحدها. البطاقات من `/materials` بالحالة التحريرية، 20 لكل عمود، كل 15 ثانية. الأعمدة الست من الخطة، و«جاهز للإنتاج» هي `accepted`. البطاقة تعرض الأولوية والزمن المنقضي وشارة الحجز، واللوحة تعرض العاجل المفتوح والمتأخر عن الإقرار وآخر الإيصالات. لا مهلة تجاوز لكل بطاقة: العقد لا يعرّف مهل الحالات بعد، فيُعرض عدّاد المتأخر عن الإقرار من اللقطة.
## مؤسسات المشترين (#203 بند 21 و31)

صفحة `/ar/buyer-organizations` لمدير النظام (إنشاء المؤسسة ومديرها الأول، وتفعيلها وتعليقها ومقاعدها) وللمالية قراءة. وصفحة `/ar/organization` لأعضاء المؤسسة: ملفها لهم جميعًا، وتعديله وإدارة الأعضاء (دعوة، وتغيير الدور، وتعليق) لمديرها. حساب المشتري (`organization_id` أو دور مشترٍ) لا يرى إلا المتجر ومؤسسته، ويُعاد من أي صفحة طاقم إلى المتجر. عزل المستأجرين في الخادم، ويكرره الـBFF: مشترٍ يطلب مؤسسة غير مؤسسته يأخذ 404 دون سؤال الخادم. الردود قوائم بيضاء (`safeOrganization` و`safeMember`)، ورمز الدعوة (#289) يمر في رد الإنشاء الأول وحده بعد فحص شكله، ويُعرض مرة في الذاكرة بلا زر نسخ ولا تخزين، ويزول بالإخفاء أو مغادرة الصفحة؛ التكرار بالمفتاح نفسه لا يعيده. الاختبارات في `tests/buyer-organizations.test.ts` و`e2e/buyers.spec.ts`.

## قوالب التراخيص (#203 بند 32)

صفحة `/ar/license-templates` لأدوار `x-roles` في v0.3: مدير النظام ومسؤول الحقوق يكتبان، ورئيس التحرير والمالية يقرآن. القائمة والقراءة المفردة بقائمة بيضاء (`safeTemplate`)، والـ ETag رقم الإصدار. الحفظ على قالب قائم يكتب إصدارًا جديدًا بـ `If-Match`، و412 يحفظ النموذج. `templateInput` يطبّق قواعد العقد قبل الإرسال: الاسم والشروط والنسب باللغتين، والمدة إلزامية للتحريري لمدة والحصري، والحصرية 24–168 ساعة للحصري وحده، والإقليم برموز دول من حرفين، و`ai_training` محظور دائمًا. التفريغ لا يُعرض تسليمًا (R11). القيم والحدود يطابقها `contract-drift`. الاختبارات في `tests/license-templates.test.ts` و`e2e/license-templates.spec.ts`.

## موادي للمراسل (#203 بند 14)

صفحة `/ar/my-materials` لدور المراسل. أحدث 100 مادة من `/materials` بمرشّح `reporter_id` للمستخدم نفسه، مع عدّاد لكل حالة تحريرية، وقسم لما يحتاج إجراءً منه (طلب تعديل أو رفع فاشل). ملاحظة المشرف تأتي من `/materials/{id}/transitions`: الـ BFF يعيد السبب وتوقيته (`reporterNote`) لانتقالات `needs_changes` و`rejected` وحدها، ولصاحب المادة وحده بعد قراءة المادة؛ وغيره يرى الانتقالات بلا سبب كما كان. الاختبارات في `tests/review-bff.test.ts` و`e2e/my-materials.spec.ts`.

## الرفع من الحاسوب (#88)

صفحة `/ar/upload` لأدوار الرفع في العقد بعد #193: المراسل والمشرف والمنتج ورئيس التحرير: اختيار ملفات الكاميرا الكبيرة، ثم بيانات المادة الثابتة والنموذج الديناميكي، ثم لكل ملف بصمة SHA-256 في Worker، ثم `POST /uploads`، ثم tus مباشرة إلى `tus_endpoint` بأجزاء `part_size_bytes`، مع رمز ingest من `POST /uploads/{id}/web-ingest-token` عبر الـBFF. بعد آخر بايت تتابع الصفحة `GET /uploads/{id}` حتى الإيصال، وصفحة المادة تعرض الحالات الثلاث ورقم الإيصال. القرار وحدوده في إضافة ADR 0014.

- `WEB_TUS_ORIGINS` قائمة أصول tus المسموحة؛ الـBFF يرفض غيرها قبل أن يصل رمز الرفع إلى المتصفح، وتدخل في `connect-src`. الفراغ يعطّل الرفع.
- الاستئناف بعد إغلاق التبويب: إعادة اختيار الملف نفسه (الاسم والحجم ووقت التعديل). السجل في IndexedDB بلا رموز ولا اسم ملف، ويُمسح عند الخروج أو الإبطال وعند فتح صفحة الدخول.
- 401 من البوابة يجدّد رمز ingest؛ 401 من الـBFF يوقف الرفع ويخرج المستخدم. لا يُستدعى `/complete` في مسار tusd.
- التشغيل الحقيقي عبر البوابة يحتاج CORS من tusd لأصل الويب مع `Ingest-Token` (عند مالك البنية).

الفحوص: `tests/upload-bff.test.ts` (القوائم البيضاء والدور وCSRF والأصول ومفتاح عدم التكرار والبصمة بالشرائح)، و`e2e/upload.spec.ts` على خادم tus اصطناعي في `scripts/fixture-api.ts` بفحص رمز ingest وCORS: رفع بالأجزاء مع 401 وقطع اتصال ثم الإيصال، واستئناف بعد إغلاق التبويب من إزاحة الخادم، وإيقاف الرفع عند الإبطال ومسح السجل، ومنع غير المراسل.

القياس: `TUSD_BIN=<tusd v2.10.1> npm run measure:upload` بعد `npm run build` ومع Redis: ملف اصطناعي 1 GiB من Chromium إلى tusd محلي حقيقي، مع قتل tusd عند 40% وإعادته؛ النتيجة في `docs/measurements/web/`.

## مركز الرفع (#203 بند 3)

قائمة «رفعات لم تكتمل» في صفحة الرفع تأتي من `GET /uploads` (جلسات المستدعي غير النهائية، #161) عبر الـBFF، بالحقول الآمنة وحدها: لا رمز ولا عنوان tus ولا اسم ملف. ما يقابله سجل محلي يُستأنف بإعادة اختيار الملف، وما لا يقابله (جهاز آخر، أو سجل ممسوح) يُعرض بلا استئناف. وكل جلسة تُلغى على الخادم بـ `DELETE /uploads/{id}`، فتُبطَل رموزها ويُحذف ما وصل منها. زر «إلغاء» أثناء الرفع يلغي الجلسة على الخادم أيضًا. السجل المحلي لجلسة لم تعد جارية على الخادم يُمحى.

### «الوارد الآن» (#203 بند 5، ADR 0024)

لوحة غرفة الأخبار تعرض `uploads_in_progress` من اللقطة: نوع الملف والأولوية وشريط النسبة وزمن آخر تقدّم، والعاجل بحدّ أحمر، ورابط المادة. `safeDashboard` يأخذ المعرّفات والأرقام وحدها ويحصر المستلم في الحجم. الحقل اختياري في العقد، فغيابه يُعرض «غير متاح بعد» لا «لا رفع جارٍ». عدّاد التصعيد هو «متأخر عن الإقرار» في اللقطة نفسها.
## الكتالوج (#203 بندا 28–29، عقد v0.3)

`/ar/store` و`/ar/store/{listing_id}` لأدوار الكتالوج في `x-roles` (الإدارة والحقوق ورئيس التحرير والمالية)، وأدوار المشترين تأتي مع #192.
- **البحث:** `GET /catalog` بمرشحات العقد وحدها (`catalogQuery`).
- **العرض:** عرض المشتري بقائمة بيضاء مغلقة (`safeCatalogItem`). يوم التصوير بلا ساعة، ولا إحداثيات ولا مدينة ولا معرّف مراسل.
- **المعاينة:** `catalog/{id}/preview` يبث الرابط الموقّع (`preview-url`، مشتق `watermarked_preview`) من الأصل نفسه عبر `streamSigned` المشترك مع معاينات المواد. لا يصل الرابط إلى المتصفح، وأصله من `WEB_MEDIA_ORIGINS`. فوقه طبقة بهوية المشاهد، ولا زر تنزيل.
- **التراخيص:** العروض بأسعارها، والحصري يُعطَّل حين لا يتاح. السلة والدفع المستضاف ينتظران عقد الطلبات.

## إدارة النماذج (#83)

صفحة `/ar/forms` و`/en/forms` تعرض `/forms` و`/forms/{version}` و`/forms/current` بالعميل المولّد. المدير ورئيس التحرير يقرآن الإصدارات، والمدير وحده ينشر. النسخ من إصدار قديم ينشئ مسودة برقم **الحالي + 1**؛ لا تعديل أو حذف لإصدار منشور (ADR 0003). يمكن إضافة الحقول وحذفها وترتيبها، وتعديل التسميات والمساعدة باللغتين، والخيارات والقيود والشرط والقيمة الافتراضية وأنواع المواد ووسم «مرشّح بحث». الوسم يطلب مراجعة الفهرسة ولا يعد بإنشاء فهرس فورًا.

- الأنواع العشرة تُولَّد من `upload-form.json`؛ الموقع ظاهر لكنه معطّل، ولا خيار لتفعيل الحساسية، امتثالًا لبوابة v0 الحالية.
- حقل `attachment` الجديد يبدأ بقيود PDF و10 MiB (10,485,760 بايت) قابلة للتعديل؛ هذه قيود تعريف الحقل، وليست تفعيلًا لرفع المرفقات. اختيار ملف في معاينة النموذج يتحقق محليًا من MIME والحجم فقط ولا يرفع بايتات الملف، وقيم المعاينة لا تدخل نشر تعريف النموذج. `DynamicForm` يستبعد المرفقات من قيم الإرسال أيضًا؛ مسار رفع المرفقات غير منفّذ حاليًا. وفق `contracts/schemas/attachment-value.json` ستكون القيمة مراجع جلسات رفع للمادة نفسها، والخادم يرفض الآن أي قيمة مرفق غير فارغة بـ422 `dynamic_fields_invalid` حتى إضافة نوع الجلسة `attachment`. مسار `/upload` الحالي خاص بملفات المادة ولا يُستعمل هنا لرفع مرفق؛ لا ادّعاء بحفظ مرفق أو معالجة أصله ضمن هذه التذكرة.
- `scripts/generate-form-validator.mjs` يولّد مدققًا مستقلًا من المخطط المرجعي باستخدام Ajv المثبّت أصلًا، وقت توليد العميل فقط. لا ترجمة مخطط ولا `eval`/`new Function` في المتصفح؛ تبقى CSP كما في ADR 0014. مكتبتا Ajv وajv-formats في اعتماديات التشغيل لأن الناتج يستعمل مساعداتهما. `check:client` يقارن المدقق وقائمة الأنواع أيضًا؛ لا مخطط يدوي موازٍ.
- معاينة المسودة تستعمل `DynamicForm` نفسه، مع اختيار اللغة ونوع المادة. قيم تجربة المعاينة لا تدخل جسم النشر ولا تُرفع، وتعديل الحقول يبطل المعاينة السابقة. النشر يتطلب معاينة صالحة ثم تأكيدًا؛ حد جسم النشر 64 KiB في الواجهة والـBFF، مع فحص البايتات أثناء قراءة الجسم حتى دون Content-Length.
- الـBFF يحصر كتابة النماذج في `POST /forms`، ويتحقق مجددًا من هوية المستخدم ودوره وOrigin وJSON ومفتاح عدم التكرار و`If-Match` لإصدار المصدر الحالي (صفر لأول نشر)، والمخطط والمفاتيح الفريدة ومراجع الشروط، ويرفض الدوران في الشروط مهما كان طوله بالمدقق المشترك مع الواجهة. أي 409/412 يبقي المسودة ولا يعيد النشر تلقائيًا؛ الإلغاء وإعادة التحميل قرار صريح. الرد المفقود يعاد بالمفتاح نفسه. لا قيم في التخزين المحلي أو رسائل الخطأ الخام.
- الفحوص: `tests/form-admin.test.ts` و`tests/contract-drift.test.ts`، واختبارات المتصفح `e2e/form-admin.spec.ts`. المطابقة المشتركة تبقى `npm run test:conformance` دون تعديل `tools/acceptance/`. المتصفح يستعمل BFF وRedis حقيقيين مع API اصطناعي؛ إثبات القبول ضد API/Postgres الحقيقيين وبقية المنصات مسؤولية وكيل الجودة، ولا تدعي هذه الاختبارات إنجازه.

## رحلة إدارة النماذج مع API وPostgreSQL حقيقيين (#83)

الأداة الاختيارية `npm run measure:forms:live` تشغّل واجهتي ar/en على بناء الإنتاج، وBFF وAPI الحقيقيين، وRedis وقاعدة PostgreSQL جديدة باسم عشوائي خاص بالتشغيل. تطبّق الترحيلات المقفلة من حزمة API ثم تزرع مستخدمين ومواد اصطناعية؛ تُنهي العمليات وتحذف القاعدة الجديدة في النهاية. لا تستخدم API mocks ولا تعدّل قاعدة المصدر أو تستعمل بيانات مستخدمين. حساب PostgreSQL التجريبي يحتاج صلاحية CREATEDB. يلزم Redis تجريبي وقاعدة رقمها 10–15.

من جذر المستودع، بعد تشغيل PostgreSQL وRedis محليين ببيانات اختبار فقط:

```sh
(cd apps/api && npm ci && npm run build)
cd apps/web
npm ci
npm run build
npx playwright install --with-deps chromium --only-shell
# اضبط عنواني خدمتي الاختبار المحليتين؛ لا تُطبع كلمات المرور في السجل.
export WEB_LIVE_POSTGRES_URL='postgres://test-user:test-password@127.0.0.1:5432/postgres'
export WEB_LIVE_REDIS_URL='redis://127.0.0.1:6379/14'
WEB_FORMS_LIVE=1 npm run measure:forms:live
```

تُرفض العناوين الخارجية وأرقام Redis غير التجريبية قبل الاتصال، ولا يعمل السكربت دون العلم الصريح. ينتج `.artifacts/forms-live/measurement.json` بمخطط العقود، ورمز خروج غير صفري عند الفشل. لا يحتوي التقرير كلمات المرور أو الرموز أو عناوين الاتصال. يفرّق التقرير بين الخدمات التي بدأت فعلًا وفشل التهيئة، ويسجّل نسخة PostgreSQL والمتصفح.

الفحوص الثمانية: نشر عربي من الواجهة، تطابق current/history ولقطات PostgreSQL وحدث Outbox، قراءة مادة تحت النموذج السابق، نسخ إصدار قديم والنشر بالإنجليزية، تعارض If-Match حي يحفظ المسودة، قراءة رئيس التحرير مع منع الكتابة في BFF، منع المراسل من تاريخ الإدارة، وكوكي HttpOnly وعدم تسرب التخزين/الاتصالات الخارجية. لا تمثل هذه الرحلة قبولًا كاملًا لثلاثة تطبيقات؛ النتيجة `partial` إلى اختبار مسودات iOS/Android واعتماد مالك الجودة.

**حالة التنفيذ:** أداة الرحلة لم تُشغّل بنجاح بعد. بيئة إعدادها المحلية لا تتيح Docker أو مستخدمًا غير root لتشغيل PostgreSQL، ولم يُتجاوز هذا القيد. اختبارات رفض الإعداد غير الآمن وlint تُشغّل منفصلة؛ لا تُعدّ دليل نجاح الرحلة. يلزم مالك الجودة لربط الأمر بوظيفة CI ذات PostgreSQL وRedis وحفظ النتيجة بعد تشغيل فعلي. لا تغييرات على `.github/workflows` أو `tools/acceptance` ضمن هذه التذكرة.
