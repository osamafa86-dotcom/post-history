# acceptance

سكربت واحد لكل صف في جدول «اختبارات القبول» في `docs/plan/الخطة-النسخة-الثالثة.md`. يملكه وكيل الجودة والقبول.

## الاتفاق

- اسم السكربت = اسم الاختبار في الخطة بالإنجليزية (`upload-resume`, `field-network-upload`, `force-quit-restart`, `concurrent-load`, `invalid-file`, `proxy-accuracy`, `receipt-notification`, `dynamic-fields`, `tenant-isolation`, `pii-leak`, `cut-export`, `duplicate-payment`, `refund`, `rights-exclusivity`, `payout`, `recovery`, `availability`, `ai-eval`, `performance`, `urgent-template-export`, `task-killers`, `timestamp-alignment`).
- كل سكربت يطبع المعيار الذي يختبره، ويكتب نتيجته بمخطط `contracts/schemas/measurement.json` في `docs/measurements/acceptance/`.
- ما يحتاج جهازًا فعليًا يُكتب سكربتًا خطوة بخطوة يجريه المشرف الميداني ويسجّل النتيجة بالمخطط نفسه.
- `form-conformance/`: اختبار المطابقة المشترك لراسم النماذج على الويب وiOS وأندرويد من مخطط واحد.

## التشغيل

```bash
cd tools/acceptance && npm ci
node run.mjs --list                          # الأسماء والمعايير وأيها آلي أو ميداني أو ينتظر حزمته
node run.mjs pii-leak tenant-isolation       # يكتب docs/measurements/acceptance/<التاريخ>-<الاسم>-<وصف>.json
node run.mjs all --dry-run                   # كل الأسماء دون كتابة نتائج؛ المنتظر منها «pending» لا فشل
npm test                                     # اختبارات السكربتات نفسها على خوادم وهمية
node validate-results.mjs                    # بوابة CI على كل ملف نتيجة في docs/measurements/
```

الخروج: `0` سليم أو منتظر، `1` فشل معيار، `2` البيئة غير متاحة فلم يُقَس شيء (لا ملف نتيجة).

## الحالة

| الاسم | الحالة |
| --- | --- |
| `pii-leak` | حقيقي. حي ضد الخادم (الاستجابات والإشعارات والأحداث وسجلات الخادم بكناري إحداثيات وعناوين). `shot_at` كاشف خارج غرفة الأخبار فقط (قرار المالك)؛ المشتقات والتصدير والقنوات الخارجية لم تُغطَّ بعد فالنتيجة `partial`. ساكن (أمثلة العقد وحمولات Outbox ومخططات الاستجابة وأمثلتها + ضوابط إيجابية تثبت أن الكاشف يرى ما يرفضه العقد)، وحي بـ `PII_BASE_URL` وكناري. ملفات `waivers/*.json` تسجّل ما هو حقيقي ورُفع لمالكه؛ الاستثناء يسقط النتيجة إلى `partial` ويصير فشلًا إن زال سببه. |
| `tenant-isolation` | هيكل الحالات (مصفوفة الأدوار × العمليات، النطاق = 404، حجب `x-permissions`، تسريب القوائم) يُبنى من `x-roles` و`x-permissions`، وينفَّذ بـ `TENANT_BASE_URL`. v0 بلا مؤسسات فالجزء المؤسسي يُضاف مع المرحلة التجارية. |
| `upload-resume` | حقيقي ضد tusd: قطع الاتصال أثناء PATCH، HEAD، استئناف من آخر ما وصل على مجمّع اتصالات جديد، وتطابق SHA-256. البصمة من S3/MinIO مباشرة (`UPLOAD_S3_*`) لأن compose يعطّل التنزيل، وإلا من GET. حجم افتراضي 64 ميغابايت للـ CI؛ معيار البوابة `UPLOAD_SIZE_MB=5120` (`manual/plan-size.md`). |
| `duplicate-payment` | **بديل مؤقت**: `Idempotency-Key` على كل كتابة (بلا مفتاح/مفتاح مشوّه = 422، تكرار = الاستجابة الأولى، جسم مختلف = 422، متزامن = مرة واحدة). لا يدّعي معيار الدفع. |
| `invalid-file` | الخطّاف الداخلي (رفض واضح، دفعة تخلط الجيد والرديء، عدم التعليق) ثم الوصول إلى `failed` بالسبب الصحيح (`checksum_mismatch` و`storage_error` و`invalid_file`) مع بقاء الجيد في الدفعة موثَّقًا. الملف التالف الترميز للوسائط: يقيسه `scripts/media-e2e.mjs` جزئيًا (قوائم HLS وconcat بامتداد فيديو وملف مقطوع ← `failed` بسبب `invalid_file` بلا مشتق ولا اتصال خارج الحاوية)؛ ترميز غير مدعوم من هاتف حقيقي ورسالة الرفض على الهاتف لم تُقَس. |
| `receipt-notification` | ثلاثة قياسات: الإنشاء ← مهمة المشرف (20 تشغيلًا)، والتحقق ← إشعار الإيصال برقمه وبصمة الخادم، والتصعيد بمهلة محقونة (محرر الأخبار ثم مدير النظام، والمُقَرّ لا يُصعَّد). تعيين المشرف عند الإنشاء بقرار المنسّق، و`upload.verified` يحدّث الحالة ويُشعر المراسل بالإيصال دون تعيين ثانٍ (يُختبر الأمران). النتيجة `partial` لغياب عامل الوسائط وتجربة الأجهزة. |
| `concurrent-load` | 60 رفعًا متزامنًا (CI: 1 ميغابايت عبر الخطّاف وS3؛ يدويًا: 2 غيغابايت عبر tusd، انظر `manual/plan-size.md`) ومقارنة زمن الإشعار مع التشغيل المنفرد. حد «لا تدهور»: p95 أقل من 5 أضعاف المنفرد أو +10 ثوان، **معيار عامل حتى التجربة الميدانية** (قرار المنسّق)، ويُغيَّر بـ `LOAD_MAX_RATIO` و`LOAD_MAX_EXTRA_S`. لا قياس لقرص خادم الرفع. |
| `performance` | زمن قراءة الواجهة تحت حمل (قائمة، تفصيل، صندوق) ويفشل عند p95 فوق 2 ثانية؛ البحث النصي ومعاينة 10 دقائق غير موجودين فلا يُدَّعيان. |
| `dynamic-fields` | الجزء المشترك (`form-conformance/`) وحيًّا على الخادم: نشر إصدار، بوابة v0، التاريخ المقروء، إكمال مسودة قديمة بإصدار أحدث، وكل الحالات المشتركة عبر `POST /materials`. `pass` يتطلب أيضًا نتائج web وios وandroid متطابقة. |
| `proxy-accuracy` | حقيقي على الحزمة الكاملة في compose (`scripts/media-e2e.mjs`، وظيفة `media-e2e` في `acceptance.yml` على الطلبات فقط): مقطع هاتف اصطناعي (VFR وفجوة وبداية 5 ث ووسوم iPhone كاشفة) يُرفع عبر `POST /uploads` وtusd ويستهلكه عامل الوسائط حتى `verified` (بصمة الخادم = بصمة العميل، إيصال)، فتظهر النسخة الخفيفة في حاوية الوسائط تحت `derived/<material_id>/` وتحفظ `start_pts` وعدد الإطارات، ويقع القص عند 10 نقاط عشوائية ضمن 40 مللي ثانية، والأصل لم يُمس (ETag وبصمة)، ولا أثر للوسوم في سجل العامل ولا قاعدة البيانات ولا الـ API ولا وسوم النسخة. مقطع 1080p لدقيقتين يعطي زمن «اكتمال الرفع ← توفر النسخة» رقمًا معلوماتيًا. **`partial` دائمًا**: HDR لم يُقَس، والمقاطع اصطناعية لا ملفات هاتف، والمصغّرة لا يولّدها العامل بعد. التشغيل المحلي بلا tusd: `HOOK_BASE_URL`+`HOOK_TOKEN` بدل `MEDIA_E2E_TUS_URL`. **المحاذاة الصوتية** (`MEDIA_E2E_ALIGNMENT=1`، مفعّل في CI لأن compose يشغّل العامل بـ`MEDIA_ENABLE_ALIGNMENT`): نسخة هاتف 240p تبدأ بعد الأصل بمقدار معلوم وطوابعها مصفَّرة تُرفع أولًا (`kind=proxy`) ثم الأصل (30 ث بمعدل متغير وصوت ضجيج بغلاف متغير)؛ يجب أن يسجّل الخادم الإزاحة موثوقة ضمن 40 مللي ثانية من المبنية عمدًا وباسم أصل المادة المتحقق، وأن يحملها `Material.files` أرقامًا فقط؛ تُكتب نتيجة `timestamp-alignment` منفصلة (`partial`: مقطع اصطناعي واحد، وترتيب الرفع نسخة ثم أصل فقط). |
| `task-killers` | ميداني: `field/task-killers.md` ثم `field/record-card.mjs`. |
| `reservation-conflict` / `optimistic-concurrency` / `admin-quorum` / `notification-delivery` / `download-url` | بوابة النواة، خلف `CORE_ACCEPTANCE=1` حتى يُدمج عمل الخادم (#69 و#75): تعمل في `live/run.mjs` (الأربعة الأولى) وفي وظيفة media e2e (`download-url`). `admin-quorum` يأخذ أوامر سطر الأوامر ثنائي الأشخاص من `QUORUM_CLI_ONE/GUARD/TWO` وبدونها `partial`؛ `notification-delivery` يحتاج `NOTIF_ESCALATION_S` للتصعيد وإلا `partial`؛ و`NOTIF_RULES=1` (من `RULES_ACCEPTANCE` في سير العمل) يقيس قواعد الإشعارات الإدارية والتصعيد الفعلي بعد خطوة 60 ثانية وبدونه `partial`؛ `download-url` يحتاج `DL_WAIT_EXPIRY=1` لينتظر الانتهاء الفعلي وإلا `partial`. |
| `ai-eval` | تغطية أدلة لا تقييم: يقرأ `docs/measurements` ويبيّن أيّ الأجزاء الخمسة (التحريف الوقائعي، الرفض لكل مزوّد، الأسماء المختلقة، تصحيح الإنسان والكلفة، تحوّل المرفوض إلى المسار المحلي) له نتيجة مسجَّلة وفي أي ملف. مفاتيح الدليل المنتظرة مذكورة في رأس السكربت لتصل نتائج الذكاء الاصطناعي دون تعديله. **`partial` دائمًا** حتى توجد الخمسة من مجموعة الـ100 بحكم بشري؛ لا يفتح تسجيلًا ولا يرسل شيئًا. |
| `cut-export` | حزمة تصدير المونتاج (`workers/media/.../export.py`) على مقطعين اصطناعيين بوسوم كاشفة مزروعة: هاتف (معدل إطارات متغير، أول طابع 3.5 ث، تدوير 90) وHDR (HEVC 10 بت HLG). تبني الحزمة بشفرة العامل نفسها وتفحص: محتوياتها وبصماتها، وأن تيارات `clip` لم تتغير (الترميز والحجم والتدوير ووسوم HDR وعدد الإطارات)، و10 نقاط قص عشوائية وإزاحة الصوت عن الصورة ≤ 40 ms وحفظ أول طابع، وأن EDL وFCPXML يغطيان المقطع، وغياب الوسوم والموقع، وأن الأصل لم يُمس. في وظيفة media e2e؛ محليًا يحتاج ffmpeg وffprobe وpython3؛ `CUT_PACKAGE`+`CUT_ORIGINAL` لفحص حزمة جاهزة، و`CUT_BUILD_CMD` لبنائها بأمر آخر (مثلًا داخل صورة العامل). **`partial` دائمًا**: لا محرر في النواة فلا قص حقيقي بنقاط يختارها إنسان، ولم يُجرَّب الاستيراد في Resolve وPremiere وFinal Cut، ولا ملف هاتف حقيقي، وFFmpeg المشغِّل ليس المثبّت في صورة العامل. |
| `c2pa-manifest` | شرط تفعيل `MEDIA_ENABLE_C2PA` (ADR 0060). مقطع هاتف H.264 (وسوم وموقع ورسالة SEI مزروعة) ومقطع HDR HEVC HLG (وسوم وموقع) يمران بمساري التصدير (`strip_metadata`) ومعاينة المتجر (العلامة المائية) ثم يوقّعهما `media_worker.c2pa.sign` بسلسلة اختبار من openssl. يُقرأ الملف الموقَّع بـ `c2patool` عندنا (لا بـ `check_report` الخاص بالعامل) ويُحكم عليه بقائمة بيضاء مكتوبة في السكربت: بيان واحد، مولّد المنصة، مكوّن واحد هو المرجع المعتم `post-history:source:` وحده، تأكيدات وإجراءات من القائمة، اسم الشبكة ناشرًا وحده، حالة تحقق `Trusted` بلا رموز مفتوحة؛ وغياب القيم المزروعة وأنماط الموقع وبصمة الأصل (hex وبايتات خام وbase64) من نص البيان ومن بايتات الملف الموقَّع ووسومه؛ والملف الموقَّع جديد ويحمل صندوق C2PA والأصل لم يُمس. ضوابط: القيم المزروعة موجودة في الأصل قبل التوقيع، والمقيّم يرفض بيانًا حُقنت فيه خمسة أنواع تسريب. محليًا يحتاج ffmpeg وpython3 وopenssl وc2patool 0.28 (`C2PATOOL_BIN`) وشفرة العامل (`WORKER_SRC`). **`partial` دائمًا**: الجذر مؤقت فلا ثقة حقيقية، ووحدة المفاتيح (`signer_path`) لم تُجرَّب، ولا ملف حقيقي. ليس في CI بعد: يلزمه c2patool، وتُضاف خطوته حين تتوفر صورة العامل الحاوية له. |
| `delivery-leak` | حزمة تسليم المشتري (`media_worker.delivery.build_delivery` بالتوقيع كما تفعل `jobs.py`: أصل وصوت وخمس صور) على مقطعين اصطناعيين بوسوم وموقع (وSEI في مقطع الهاتف). يفتح الأرشيف ويحكم من الخارج بقائمة `c2pa-manifest` البيضاء وبـ `c2patool`: محتويات الحزمة المحددة وحدها، وبصمات `SHA256SUMS`، وبيان كل ملف (فيديو وWAV وJPEG) داخل القائمة بلا صورة مصغّرة، وغياب القيم المزروعة وأنماط الموقع وبصمة الأصل الخام (hex وبايتات) من **كل** ملف بما فيه `manifest.json`، والأصل لم يُمس. ضوابط: القيم موجودة في المصدر، والمقيّم يرفض حزمة حُقنت فيها قيمة. يحتاج ما يحتاجه `c2pa-manifest` وشفرة العامل ذات معامل `sign` (#276). **`partial` دائمًا** (جذر مؤقت، لا `signer_path`، لا ملف حقيقي). أخضر منذ #279 (حُذفت بصمة الأصل الخام من `manifest.json`)، ويعمل في وظيفة media e2e على c2patool صورة الوسائط كـ `c2pa-manifest`. |
| `availability` | إسقاط الخادم وقاعدة البيانات بـ `kill -9` على عملية الحاوية من المضيف (انهيار تعيده سياسة restart؛ `docker compose kill` يعدّه Docker إيقافًا يدويًا فلا يعيدها، وتلزم صلاحية root أو `AVAIL_KILL_PREFIX=sudo`) وإعادة إنشاء حاوية الخادم (النشر لنسخة واحدة) تحت قراءة متواصلة (4 عمال كل 50 مللي ثانية) عبر العنوان الذي يصله العملاء، ومادة علامة كُتبت قبل إسقاط القاعدة يجب أن تبقى مقروءة. تُقاس لكل سيناريو مدة الانقطاع حتى استقرار القراءة (‎-1 = لم تتعافَ). يحتاج `AVAIL_API_URL` و`AVAIL_TOKEN` (مراسل) و`AVAIL_COMPOSE` (أمر compose، مثلًا `infra/field-trial/trial.sh`). **`pass` يتطلب هدف تعافٍ معلنًا من الإدارة (`AVAIL_TARGET_S`، قرار 8) وتصريح المشغّل أنه مضيف التجربة (`AVAIL_TRIAL_HOST=1`)** وتعافي كل سيناريو ضمنه وسحب مادة الكناري (`[كناري] …` تُحوَّل تحريريًا إلى `rejected` بسبب `availability_canary` بيد مشرف حساب القبول `AVAIL_SUPERVISOR_TOKEN`، فالمواد لا تُحذف)؛ بدونها `partial`. على مضيف التجربة يرفض بلا `--maintenance-window` وبغير حساب القبول (`AVAIL_ACCEPTANCE_EMAIL`). نسخة خادم واحدة: النشر انقطاع. |
| `reporter-identity-access` | ADR 0021، خلف `CORE_ACCEPTANCE=1` في `live/run.mjs`: الاسم الحقيقي للمراسل (كناري يبذره `live/seed.mjs` مشفرًا) يظهر لحامل الصلاحية التي يحددها الإعداد وحده، والتبديل يسري في الطلب التالي بحدث `setting.changed` واحد بلا اسم، والقيمة نفسها لا تكتب حدثًا، والإعداد للمدير وحده بسبب مرمّز. بلا الكناري `partial`. لم يُقَس التبديل عبر عمليات خادم متعددة. |
| `transcript-draft` | عامل التفريغ المحلي طرفًا لطرف (تذكرة 10)، خلف `AI_ENABLE_TRANSCRIPT=1`: مقطع اصطناعي بكلام عربي (espeak-ng أو `TD_SPEECH_FILE`) ← `transcript` و`captions` مسجَّلان، المسودة لا تغيّر المادة، JSON على خط زمن الأصل ومحلي، وWebVTT صالح بـRTL، وبايتات الروابط بصمتها المسجلة، وزمن التفريغ p95 مقابل مدة المقطع (`TD_LIMIT_RATIO`)، ومقطع موسوم بالحساسية، وغياب الخروج من حاوية العامل (`TD_EGRESS_CMD`). دقة الكلمات في `tools/asr-bench` لا هنا. |
| `field-upload-1gb` | ميداني (المرحلة (ب)): `field/field-upload-1gb.md` ثم `field/record-card.mjs`؛ بطاقة لكل جهاز. |
| `force-quit-restart` | ميداني: `field/force-quit-restart.md` (أربعة سيناريوهات: قتل قسري، نفاد البطارية، إعادة تشغيل، مساحة أقل من 1 غيغابايت) والحكم آلي من البطاقة. |
| `timestamp-alignment` | ميداني + وسائط: `field/timestamp-alignment.md`؛ عشرة مقاطع VFR بفجوات، والإزاحة تقيسها أداة الوسائط وتُسجَّل باسمها، ينجح عند ≤ 40 مللي ثانية في كلها. |
| `recovery` | الشطر القابل للقياس في خط الإنتاج (`scripts/recovery.mjs`، خطوة في وظيفة `db` في `ci.yml`): قاعدة مهاجَرة ومبذورة (`smoke.sql` بـ COMMIT) تُنسخ بـ `pg_dump -Fc` وتُستعاد بـ `pg_restore` (يعمل بمسار بحث فارغ) إلى قاعدة جديدة، ويجب تطابق عدّ الصفوف لكل جدول وصلاحية كل القيود. جُرِّب أن الفحص يلتقط علة #71 (outbox_events: 3 قبل، 0 بعد) ويمر بعد إصلاحها. **`partial` دائمًا**: النسخة المعزولة لدى المزوّد الثاني وعينة الأصول وهدفا 15 دقيقة/4 ساعات بحجم حقيقي لم تُقَس. بلا `RESTORE_DATABASE_URL` يبقى الصف pending. |

### حزمة قبول التجربة الميدانية (ضد مضيف بعيد)

```bash
FT_ACCOUNTS='{"reporter":{"email":"…","password":"…"},"reporter_b":{…},"supervisor_b":{…}, …بقية الأدوار غير مدير النظام}' \
  node tools/acceptance/run.mjs --target https://<المضيف> --confirm [--out-dir=<مجلد>] [--allow-publish-form]
```

أمر واحد يشغّل السكربتات الحية ضد المضيف بحسابات اختبار تسلّمها البيئة (لا أسرار في الكود ولا في السجل): `tenant-isolation` و`pii-leak` و`upload-resume` (جلسة رفع حقيقية بمقطع اصطناعي صالح، والبصمة يؤكدها الخادم) و`media-remote` (واجهة وtus فقط: مقطع هاتف يتحقق وتظهر نسخته الخفيفة ومصغّرته ولا أثر للوسوم الكاشفة في الواجهة، وملفات مموَّهة بامتداد فيديو تفشل `invalid_file`) و`session-revocation`، ثم مجلد نتائج بمخطط القياس و`REPORT.md` موحّد. `dynamic-fields` يعمل دائمًا؛ على مضيف التجربة بالقراءة وحدها (النموذج الحالي والسابق مقروءان، `partial`)، أما نشر إصدار جديد يصير الحالي (`--allow-publish-form`) فمحلي فقط على compose ويُرفض لأي مضيف آخر. **تكتب الحزمة على المضيف** (مواد اصطناعية بإحداثيات كناري، ورفع مقاطع، وإبطال كل جلسات حساب المراسل التجريبي) فلا تعمل بلا `--confirm`، ولا مع `http` إلا للـloopback، ولا بلا الأدوار المطلوبة (`reporter` و`reporter_b` و`supervisor_b`؛ الأولان من مكتب غير مكتب الثالث). **أدنى دور لكل سكربت:** لا يُعطى مضيف التجربة حساب `system_admin` أصلًا؛ لا يُقرأ ولا يُدخَل به إلا مع `--allow-publish-form` (نشر النموذج)، وهذا للتشغيل المحلي على compose وحده، فمصفوفتا `tenant-isolation` و`pii-leak` تعملان بلا مدير نظام (لا يلزم لإثبات الرفض) و`session-revocation` لا تقرأ أحداث الرفع الجاري عن بُعد. وفي ذلك التشغيل المحلي: (١) TOTP إلزامي للحساب وبيانه `totp_secret` (سداسي عشري) في `FT_ACCOUNTS.system_admin`؛ دخول بكلمة المرور وحدها يُرفض ويُخرَج منه فورًا؛ (٢) `FT_SUSPEND_ADMIN_CMD` إلزامي قبل البدء، وهو الأمر الذي يعلّق الحساب على المضيف (`cli:set-admin-status`، يقرأ رموز TOTP للمؤكِّدين من هذه الطرفية)؛ (٣) يعمل الأمر في `finally` حتى لو فشلت خطوة، ثم تتحقق الحزمة أن الحساب لا يدخل بعده؛ مدير نظام ما زال يدخل = خروج 1 ورسالة `ADMIN STILL ACTIVE`. السطر `system_admin:` في رأس التقرير يذكر الحالة. ما يحتاج قاعدة بيانات أو تخزينًا أو سجل العامل (دقة القص، سلامة الأصل، خروج الاتصالات، بايتات المصغّرات) يبقى في `media-e2e` على compose ويُذكر في رأس التقرير. التجربة على مضيف تتحكم به: `field-trial/rehearsal-accounts.mjs` يطبع حسابات اصطناعية لقاعدتك (وهكذا تجري وظيفة `media-e2e` في CI التمرين على compose). قائمة الفحص الميدانية: `docs/ops/field-trial-checklist.md`.

**الرفع بالرمز:** كل سكربت يرفع (`upload-resume` و`media-remote` و`session-revocation` و`media-e2e` و`download-url` و`transcript-draft`) يرسل مع كل طلب tus رمز الجلسة في `Authorization` ورمز ingest في `Ingest-Token` حين يُضبط `INGEST_SIGNING_KEY` (مسار PEM لمفتاح اختبار تثق به البوابة، و`INGEST_KID` افتراضيه `k1`)، ويوقّعه محليًا كدخان البوابة (`lib/ingest.mjs`)؛ بلا المفتاح يبقى السلوك كما كان. الحزمة الميدانية تأخذهما من `FT_INGEST_SIGNING_KEY` و`FT_INGEST_KID`، ومن `FT_RESOLVE` (`اسم=عنوان,…`) للوصول إلى اسم على عنوان محدد كما يفعل الجهاز بعد DNS، و`FT_TUS_URL` لنطاق الاستقبال. هذا لمنصة نتحكم بها (CI، compose محلي): مفتاح توقيع مضيف حقيقي لا يُسلَّم لسكربت، والجهاز الحقيقي يأخذ رمزه من `POST /uploads/{id}/ingest-token` بعد شهادة جهازه.

### اختبارات الأمن خارج جدول الخطة (SEC-01)

| الاختبار | الحالة |
| --- | --- |
| `session-revocation` | حقيقي على compose (`scripts/session-revocation.mjs`، وظيفة `media-e2e` على الطلبات فقط): جلستان لمراسل؛ إبطال إحداهما (`DELETE /auth/sessions/{id}`) ثم كل الجلسات (`POST /auth/logout`)، ويقيس **ثواني من رد الإبطال إلى أول رفض** لرمز الوصول ورمز التجديد، ولرمز رفع لم يُنشأ به رفع عند tusd-proxy. «خلال ثوانٍ» صار رقمًا مقترحًا ≤ `REVOKE_MAX_S` (5 ث افتراضيًا) يُذكر في النتيجة (`criterion_proposed_s`) وتُعدَّل بالقياس. الرفع الجاري: يبقى مقبولًا عند الجزء التالي لأن tusd لا يسأل الخادم عن PATCH لاحق؛ ثغرة معروفة في `waivers/session-revocation.json` (تُغلقها بوابة ingest، ADR 0011) فالنتيجة `partial`، وتصير فشلًا إن زال سببها. لم يُقَس: واجهة الإدارة، وزمن الهاتف، ونسخ خادم متعددة. |
| `emergency-wipe` | ميداني: `field/emergency-wipe.md` وبطاقة لكل منصة (`emergency-wipe.ios.card.template.json` و`emergency-wipe.android.card.template.json`)؛ المخازن من قوائم #56 (iOS) و#57 (أندرويد)، والحاكم آلي: كل مخزن فارغ، المسح متصلًا وبلا اتصال ≤ 5 ث، الجلسة غائبة عن الخادم والرمز القديم مرفوض، والدخول يعمل بلا إعادة تشغيل. `partial` حتى تُملأ بطاقة جهاز iOS فعلي وأندرويد فعلي. |
| الباقي | ملف لكل اسم يطبع المعيار ويرجع `pending` حتى توجد الحزمة المقيسة. |

لا يكتب أي سكربت `pass` دون أن يكون الدليل كله حاضرًا: فحص لم يُنفَّذ (مثل الجزء الحي) يُنتج `partial`، ويرفض `validate-results.mjs` أي `pass` مع مقياس يعلن أن الدليل ناقص.

## تقرير القبول الموحّد

`node report.mjs [--out=REPORT.md]` يجمع كل ملفات `docs/measurements/` (كل الأدوات) في جدولين: صفوف جدول اختبارات القبول الاثنين والعشرين بحالة كل صف (لا نتيجة ظاهرة لا مخفية)، وكل النتائج الأحدث لكل أداة/اختبار/ملف شبكة بأرقامها. يعمل في CI ويُكتب في ملخص الوظيفة، والنسخة المرجعية للبوابة `docs/measurements/REPORT.md` تُولَّد عند مراجعة البوابة. الصف لا يكون `pass` إلا بنتيجة `pass`، وأي `fail` في أحدث تشغيل يسحب الصف إلى `fail`.

## التشغيل الحي ضد الخادم

```bash
cd apps/api && npm ci && src/db/migrate.sh up && npm run build      # DATABASE_URL لقاعدة فارغة مرحَّلة
cd ../../tools/acceptance && node live/run.mjs [--dry-run]
```

جلسات الرفع كلها من `POST /uploads` الحقيقي كما يفعل تطبيق المراسل؛ لا إدراج مباشر في القاعدة إلا لدفع جلسة إلى حالة لا يبلغها الـ API بسرعة (منتهية الصلاحية، أو `completed` بلا ملف) في حالات الخطّاف. يبدأ `live/run.mjs` الخادم المبني بأسرار مؤقتة عشوائية، ويزرع `live/seed.mjs` قاعدة اصطناعية (مكتبان، مستخدم لكل دور، مراسل ومشرف في مكتب آخر، مواد بإحداثيات وعناوين كناري)، ثم يشغّل: `tenant-isolation`، `duplicate-payment`، `invalid-file`، `receipt-notification`، `concurrent-load`، `performance`، ثم `pii-leak` (يقرأ سجلات كل ما سبقه)، و`dynamic-fields` أخيرًا لأنه ينشر نموذجًا يصير الحالي بحقول مطلوبة. بـ `LIVE_REDIS_URL` و`LIVE_S3_*` يتحقق الخادم فعليًا ويُشارك حد المعدل في Redis؛ بدونهما تُشغَّل الأجزاء التي لا تحتاجهما فقط. `--only=a,b` يشغّل بعضها. بلا `--dry-run` تُكتب النتائج في `docs/measurements/acceptance/`. وظيفة `live` في `.github/workflows/acceptance.yml` تشغّله بـ `--dry-run`.

العمليات التي لم تُنفَّذ بعد في الخادم (404 دون اعتماد) تُحسب `unimplemented` وتُبقي النتيجة `partial`؛ تتحول إلى حالات فعلية تلقائيًا حين تُنفَّذ.
