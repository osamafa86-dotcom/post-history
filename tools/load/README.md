# اختبار حمل compose

المهمة 3 من #352؛ اختبار القبول رقم 4 `concurrent-load`. يستعمل autocannon لعدم توفر k6 محليًا، وعميل tus المشترك للقطع الحقيقي للاتصال والاستئناف من HEAD. لا هوك مُحاكى.

ثبّت `npm ci --prefix tools/acceptance` ثم `npm ci --prefix tools/load`. شغّل خدمات compose المحلية والعامل وoutbox على قاعدة قابلة للإزالة. جهّز حسابات اصطناعية بالأداة `tools/acceptance/field-trial/rehearsal-accounts.mjs`، وسجّل دخول الأدوار المطلوبة للحصول على رموز مؤقتة في البيئة فقط. لا تحفظ كلمات المرور أو الرموز في ملفات.

مرّر `LOAD_LOCAL_ONLY=1` و`LOAD_API_URL` و`LOAD_TUS_URL` و`LOAD_CONTAINERS` (أسماء حاويات compose مفصولة بفواصل) و`LOAD_TOKENS` (JSON بمفاتيح reporter وproducer وbuyer_admin)، ثم:

```sh
node tools/load/run.mjs
```

المدة الافتراضية 60 ثانية، تضبط بـ`LOAD_DURATION_S` بين 10 و600. السكربت يضيف 50 مادة وجلسة رفع. يولّد ملفًا اصطناعيًا مؤقتًا حجمه 50,000,000 بايت ويطلق 50 رفعًا معًا، ويقطع 13 منها مرة واحدة ثم يستأنف. ينفذ لاحقًا سيناريو API مستقلًا: 100 طلب/ث للوارد و100 للكتالوج، ويعدّ أخطاء HTTP والاتصال والمهلة ويكشف عدم بلوغ 95% من معدل الطلبات المستهدف. لا يسجّل أجسام الردود أو العناوين أو الحسابات.

`docker stats` يُقرأ دوريًا، والنتيجة تتضمن ذروة مجموع ذاكرة الحاويات المحددة وعدد العينات وأخطاء القراءة. تُكتب النتيجة عبر writeResult المشترك بعد تصديق مخطط measurement، باسم نطاق 50x50mb-api200rps وبلا استبدال ملف سابق. يُذكر طور التوقف في notes إن تعذّر اكتمال السيناريو. تُحفظ في `docs/measurements/api/`، مع p50/p95/p99 للمدد المقيسة. خطأ التهيئة أو غياب docker قبل التشغيل لا يولّد نتيجة مختلقة.

تبقى النتيجة `partial` حتى دون أخطاء: هذا حجم #352، أما الخطة فتطلب 60 رفعًا × 2 GB وعدم تدهور الإشعارات والقرص المؤقت. لا تقيس هذه الأداة القرص أو زمن الإشعار أو تطابق البصمة بعد معالجة الخادم؛ استعمل اختبار القبول الأصلي لهذه الجوانب. لا توسّع إذن التشغيل إلى خدمات حقيقية.

التحقق المحلي: اختبارات النسب المئوية وتحويل الذاكرة وحارس العناوين، وautocannon ضد خادم HTTP مؤقت للتأكد من رصد 403 ومدد الردود. **لم يُنفّذ حمل compose هنا.**
