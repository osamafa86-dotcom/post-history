# فاحص جاهزية الدمج (pr-gate)

أداة سطر أوامر تجيب: هل PR معيّن جاهز للدمج وفق قواعد المستودع؟
تقرأ GitHub API فقط (لا تعدّل شيئًا)، وتطبع كل شرط مع دليله، وتخرج برمز يصلح للبوابات الآلية.

## الاستعمال

```bash
export GITHUB_TOKEN=...        # اختياري؛ بلا رمز يعمل على المستودعات العامة ضمن حدود المعدل
node tools/pr-gate.mjs 404                       # المستودع من PR_GATE_REPO
node tools/pr-gate.mjs 404 --repo owner/name     # أو صراحة
node tools/pr-gate.mjs 404 --json                # مخرجات آلية
```

رمز الخروج: `0` جاهز، `1` غير جاهز، `2` خطأ استعمال أو اتصال.

## الشروط الثمانية

| المعرف | الشرط |
| --- | --- |
| `base` | القاعدة `main`، وليس مسودة، وبلا تعارض دمج |
| `ci` | كل check-runs على الرأس الحالي مكتملة وناجحة (تُستثنى الأسماء التي تبدأ بـ`.github`) |
| `quality` | آخر تعليق يبدأ بـ«مراجعة الجودة» (أو QA review) بلا «مانع»، وبتاريخ أحدث من آخر التزام غير دمجي |
| `security` | مثله لـ«مراجعة الأمن» |
| `owner` | سطر «مراجعة المالك: لا مانع» حين تمس الملفات حزمة مالكها غير صاحب الـPR |
| `stacking` | تحذير «مكدّس فوق #N» إن كانت ملفات الـPR مجموعة شاملة لملفات PR مفتوح آخر |
| `contracts` | أي ملف تحت `contracts/` يلزمه تعليق يبدأ بـ«موافقة المنسّق» |
| `naming` | العنوان `[<الدور>] …` والفرع `agent/<الدور>/…` بنفس الدور، ولا أسماء نماذج ذكاء اصطناعي في العنوان أو المتن أو رسائل الالتزامات |

تفاصيل:

- **الحكم الشرطي**: «لا مانع بشرط» تُظهر الحالة `pending` مع نص الشرط، وأي «مانع» آخر `fail`. عبارة «لا مانع» المجردة لا تُقرأ مانعًا.
- **حداثة الحكم**: حكم الجودة أو الأمن المؤرخ قبل آخر التزام غير دمجي (تُتجاهل التزامات الدمج) يُعدّ `pending` لأنه لم يغطِ الرأس الحالي.
- **الملكية**: تُقرأ من جدول «المسار ← المالك» في README.md (أطول بادئة تغلب)، والدور من بادئة الفرع `agent/<الدور>/`. تُعفى `docs/**` وطلبات وكلاء الجودة والأمن.
- **أسماء النماذج**: تُتجاهل سطور الإسناد الآلي المعتمدة (سطرا Co-Authored-By والجلسة) واسم ملف القواعد القديم.

## المخرجات

نص عربي: سطر خلاصة ثم جدول «الشرط | الحالة | الدليل». مع `--json`:

```json
{ "pr": 404, "ready": false,
  "checks": [ { "id": "ci", "status": "fail", "evidence": "…" } ] }
```

الحالات: `pass` ناجح، `fail` فاشل، `pending` معلّق. الجاهزية تتطلب نجاح الثمانية كلها.

## الاختبارات

```bash
node --test tools/pr-gate.test.mjs
```

تعمل على حالات JSON ثابتة في `tools/test/pr-gate/` بلا شبكة ولا تبعيات خارجية؛ تُحقَّق دالة الجلب في الاختبارات. ملف README داخل الحالة يُخزَّن نصًا صريحًا (حقل `text`) وتُحوّله دالة الجلب الوهمية إلى شكل API (base64).

## استخدامها في CI

يمكن تشغيلها كخطوة بوابة على `pull_request` مع `GITHUB_TOKEN` المدمج؛ الاقتراح يُطرح في وصف الـPR ولا تضيف هذه الأداة أي ملف تحت `.github/`.
