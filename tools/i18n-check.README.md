# فاحص الترجمة

`node tools/i18n-check.mjs --json` يخرج 1 عند نقص مورد أو نص عربي حرفي محتمل أو تعذر قراءة الموارد. JSON دون --json تُطبع نتائجه كسطور. فحص تقريبي، وليس مصدّقًا لمعنى الترجمة أو كاشفًا للنص الإنجليزي الحرفي.

## الصيغ وقائمة الاستثناءات المبررة

- JSON: تتم مقارنة المسارات المتداخلة بين رسائل العربية والإنجليزية. المفتاح المشترك يُقبل دون مقارنة القيم؛ اختلاف النص هو الترجمة المقصودة. لا استثناء بأسماء مفاتيح أو مجلدات تطبيق كاملة.
- Android: `values/` هو العربية الافتراضية كما يصرح تعليق strings.xml في المشروع؛ `values-en` للإنجليزية. تشمل المقارنة string وplurals وstring-array، وتُهمل تعليقات XML. أي نقل للغة الافتراضية يحتاج تحديث هذا القرار والفحص.
- iOS: موارد Localizable.strings حسب ar.lproj وen.lproj؛ وفي xcstrings تُعتبر لغة المصدر ممثلة بالمفتاح نفسه. يُستثنى فقط `shouldTranslate: false` المعلن داخل المورد (مثل الاسم التقني المقصود إبقاؤه)، دون استثناء آلي لكل اسم منتج أو فئة نصوص.
- النصوص البرمجية: تُهمل التعليقات، ومجلدات test وtests وe2e دون حساسية لحالة الأحرف، وملفات .test/.spec و*Tests.swift، فلا تتحول عينات الاختبار إلى نصوص واجهة.
- وحدها المحارف العربية الأبجدية تستدعي فحص النص الحرفي؛ الفاصلة العربية والفاصلان العشري والآلاف والأرقام العربية/الفارسية وحدها لا تعد نصوصًا مترجمة. إذا صاحبها نص عربي حقيقي يُبلغ عنه. لا تجاهل للأسطر التي تحمل كلمات عربية فعلية.

اختبار المجلد المؤقت يغطي الصيغ الأربع، والنقص والتعليقات وJSON التالف، والعلامات والأرقام، واختبارات iOS، والنصوص الفعلية في TSX وKotlin وSwift. التشغيل:

```sh
node --test tools/test/i18n-check.test.mjs
```

خطوة وظيفة web تحذيرية بـcontinue-on-error وتضع JSON في ملخص الوظيفة، حتى عند خروج 1. تحويلها إلى فشل يحتاج قرارًا مستقلًا.
