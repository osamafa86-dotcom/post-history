# غرفة الأخبار الاصطناعية

المهمة 2 من #352. ثبّت اعتماديات `tools/acceptance` و`tools/dev` بـ `npm ci --prefix tools/acceptance` و`npm ci --prefix tools/dev`، وشغّل compose مع migrations وAPI وtusd والعامل وoutbox. تحتاج ffmpeg في بيئة تشغيل الأداة.

مرّر من البيئة `DEMO_LOCAL_ONLY=1` و`DATABASE_URL` و`API_URL` و`ROOT_URL` و`TUS_URL` و`SP_WEBHOOK_SECRET` الخاص بالمزوّد التجريبي المحلي فقط. لا تحفظها في ملف أو PR. ثم:

```sh
node tools/dev/seed-demo.mjs
```

القاعدة يجب أن تكون قابلة للإزالة ومخصصة للعرض. الأداة تضيف بيانات ولا تحذف بيانات سابقة، ولا تعيد تهيئة القاعدة. لا تشغّلها مرتين إن أردت تعدادًا ثابتًا. فشلها قد يترك بيانات جزئية؛ أعد إنشاء قاعدة العرض قبل إعادة المحاولة.

تعيد استعمال `live/seed.mjs` كما يفعل `field-trial/rehearsal-accounts.mjs`، فتحتفظ أيضًا بحسابات ومواد القبول المساعدة (ليست قاعدة فارغة من 40 مادة فقط). تضيف ستة مراسلين إجمالًا، وتستعمل المحررين والمشرف الموجودين. تولّد مقطعًا اصطناعيًا بـffmpeg في مجلد مؤقت، وترفعه أربعين مرة عبر tus، ثم توزّع الحالات الثلاث مباشرةً في قاعدة العرض: هذه الحالات **تمثيل عرض** ولا تثبت مرور المعالجة. لا ملفات وسائط محفوظة في git.

يُعدّ الأربعون من القاعدة باستخدام معرّفات المواد التي أنشأتها الأداة فقط. تمر مادة واحدة عبر انتقال «اطّلعت» الفعلي لتنتج حدثًا وإشعارًا؛ بقية الحالات تمثيل عرض كما سبق. فحص التنزيل المؤجل لا يمنع نجاح البذرة؛ الاسترداد المكتمل يُشترط من القاعدة نفسها، ووجود فحص مؤجّل اسمه refund في نص التقرير يمنع النجاح حتى إن وُجد استرداد قديم؛ لا يُحكم بعدّاد الفحوص المؤجلة العام.

تطبع الحسابات وكلمات مرور عشوائية مرة واحدة بعد النجاح؛ تعامل مع الطرفية كسر ولا تحول المخرج إلى ملف. كلمات المرور مخزنة مجزّأة في القاعدة فقط. تستخدم رحلة الشراء المشتركة للتحقق من الدفع والترخيص والاسترداد؛ إذا لم يخدم الخادم الاسترداد تفشل الأداة بدل إعلان اكتمال البذرة. نتائج الرحلة مؤقتة ولا تنشر تلقائيًا. جميع العناوين والمدن والأسماء المعروضة اصطناعية صراحة.

لم تنفذ رحلة compose هنا؛ يلزم تشغيل الجودة على خدمات محلية قبل اعتمادها للعروض.

رسالة الفشل تذكر مرحلة ثابتة مثل materials أو sandbox_purchase أو refund_verification أو paid_order، بلا طباعة استثناء قاعدة البيانات أو مخرجات رحلة الشراء أو كلمات المرور. يظل الخروج غير صفري وتبقى البيانات الجزئية ممكنة.

## انتظار التحقق وفحص استعلام الرخصة

تنتظر المادة الأولى verified قبل انتقال المشرف. عند 412 تُقرأ نسخة وETag جديدان، بسقف 120 قراءة وفاصل ربع ثانية؛ لا تتكرر الكتابة بإصدار قديم، والفشل الفني يوقف الانتظار. مرحلة first_transition تظهر منفصلة عند الفشل. الرخصة تُقرأ عبر licenses.order_item_id ثم order_items.order_id.

لاختبار الاستعلام الفعلي دون تعديل البيانات، مرّر DEMO_LOCAL_ONLY=1 وDEMO_TEST_DATABASE_URL لقاعدة محلية مُرحّلة، ثم شغّل node --test tools/dev/seed-demo.test.mjs. الاختبار ينفذ الاستعلام داخل BEGIN READ ONLY ويتحقق من information_schema. عند غياب القاعدة يُعلن skipped صراحة؛ اختبارات المحاكاة لا تثبت صحة SQL على PostgreSQL.
